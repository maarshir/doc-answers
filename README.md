# doc-answers

[![Тесты](https://github.com/maarshir/doc-answers/actions/workflows/tests.yml/badge.svg?branch=main)](https://github.com/maarshir/doc-answers/actions/workflows/tests.yml)

Отвечает на вопросы по папке с документами: находит нужные куски и просит модель ответить строго по ним, со ссылкой на источник после каждого факта. Если ответа в документах нет, так и говорит. Для команд, у которых правила и памятки лежат в файлах, а искать в них никто не хочет.

```
$ python -m doc_answers ask "Как быстро дежурный должен ответить на сбой ночью?" --k 2
Демонстрационный режим (нет ANTHROPIC_API_KEY или GROQ_API_KEY): модель не вызывалась.
Вот куски, которые получила бы модель, лучшие сверху:

1. [dezhurstva.md#2] dezhurstva.md, Дежурства по сайтам клиентов / Сроки реакции  (счёт 5.86, совпали: дежурн, сбо, ноч)
   На сообщение о сбое дежурный отвечает в течение 15 минут в рабочее время и в течение одного
   часа ночью и в выходные.
   ...

2. [dezhurstva.md#4] dezhurstva.md, Дежурства по сайтам клиентов / После сбоя  (счёт 4.69, совпали: дежурн, сбо)
   ...

≈475 токенов на входе (прикидка без токенизатора), не больше 700 на выходе. С ключом запрос к claude-haiku-4-5 стоил бы не больше ≈$0.003975.
```

Это настоящий вывод без ключа (сокращён многоточиями): видно, какие куски найдены и почему. С ключом модель отвечает по ним текстом со ссылками вида `[otpusk.md#1]`, а код проверяет, что она сослалась только на то, что ей дали. Настоящих ответов модели в репозитории пока нет. Документы в `examples/docs` это вымышленная памятка сотрудника вымышленной студии.

## Установка

```bash
git clone https://github.com/maarshir/doc-answers && cd doc-answers
pip install -r requirements.txt
cp .env.example .env    # и вписать ключ Groq или Anthropic; без ключа работает демонстрационный режим
```

Нужен Python 3.10+.

## Использование

```bash
python -m doc_answers ask "Сколько дней отпуска в году?"
python -m doc_answers ask "Что делать, если сломался ноутбук?" --docs путь/к/своей/папке
```

Читает `.md` (с разбиением по заголовкам), `.txt` и `.pdf` с текстовым слоем. Битый файл не роняет всё, а попадает в предупреждения.

**Бесплатно через Groq.** Ключ на [console.groq.com/keys](https://console.groq.com/keys) в `GROQ_API_KEY`. Если задан только он, ответ идёт через Groq на `openai/gpt-oss-120b`; при ответе 429 программа ждёт столько, сколько сказал сервер. Лимиты бесплатного уровня на [странице Groq](https://console.groq.com/docs/rate-limits).

**Через Anthropic.** `ANTHROPIC_API_KEY`, модель по умолчанию `claude-haiku-4-5`. Если заданы оба ключа, берётся Anthropic, а Groq включается `--provider groq` или моделью с косой чертой в имени.

Параметры: `--docs`, `--k` (сколько кусков отдать модели, по умолчанию 4), `--size` и `--overlap` (размер куска и перекрытие, 600 и 120 символов), `--model`, `--provider`, `--no-model`, `--show-prompt` (показать, что уходит модели), `--prices`.

## Как проверить качество

Ответ ломается в двух местах, и проверяются они отдельно.

**Поиск**, без модели и бесплатно: `python -m doc_answers search-eval` прогоняет 15 вопросов из `eval/questions.yaml` и показывает место куска с ответом. Настоящий итог:

```
Кусок с ответом на первом месте: 12 из 12, среди первых 4: 12 из 12.
Вопросы без ответа: 3, из них поиск сам отсеял 2; остальные должна отсеять модель (это проверяет promptdiff).
```

Примеры маленькие, поэтому 12 из 12 значит только «ничего не сломано»; с кусками по 200 символов выходит уже 10 из 12. Проверка стоит в CI.

**Ответы модели**: `python -m doc_answers export-promptdiff` выгружает те же вопросы в формат [promptdiff](https://github.com/maarshir/promptdiff-) с двумя вариантами промпта (`strict` с правилами и `plain` без них). Прогон и почему для Groq нужен `--rpm 5`: [docs/решения.md](docs/решения.md#проверка-ответов-модели-через-promptdiff).

## Что было непросто

- **Куда резать.** Маленький кусок теряет смысл, большой вытесняет другие. Режу по заголовкам, абзацам и предложениям, а перекрытие беру только целыми предложениями.
- **Заголовок это часть текста.** Кусок часто не повторяет тему раздела, поэтому цепочка заголовков участвует в поиске и видна в ссылке.
- **Не звать модель, если не на что опереться.** Если в документах нет ни одного слова из вопроса, модель не вызывается. Остальные «вопросы без ответа» должна отсеять сама модель, и в наборе есть оба случая.
- **Модели нельзя верить на слово про источники.** После ответа ссылки проверяются кодом по списку отданных кусков.
- **Отказ одной точной фразой.** Иначе программа не отличит отказ от ответа. Фраза живёт в одной константе, из неё собираются промпт, разбор ответа и проверки.

Подробнее, включая выбор BM25 вместо векторного поиска и работу с двумя поставщиками: [docs/решения.md](docs/решения.md).
